# 需求：给 8765 装机工具加「从 URL 下载安装包」

## 一、任务

给本机的 8765 装机工具（`http://127.0.0.1:8765/`）加一个**「下载安装包」**功能：在网页上粘一个 APK 的下载地址，服务端把它流式下载到项目目录，下载完成后可以直接点「安装到设备」，走现有的安装流程。

**核心场景**：现场那台电脑没有 Unity、也不想手动从 CDN 拖一个 300~800MB 的包，粘个链接就能拿到本地并装上去。

## 三、要加的功能（按这个顺序实现）

### 3.1 后端：`POST /api/download_apk`

请求体（JSON）：

```json
{
  "url": "http://cdn.vr.hoseavr.com/arasset/shenyang_palace/v18/com.hsy.sygg_v18.apk",
  "name": "可选，自定义落盘文件名；不给就从 URL 或 Content-Disposition 里取",
  "sha256": "可选，给了就下载完校验，不匹配删文件并报错",
  "expected_size": 336613183,
  "resume": true,
  "install_after": false,
  "serials": [],
  "pkg": "com.hsy.sygg",
  "act": "com.unity3d.player.UnityPlayerActivity"
}
```

行为要求：

1. **立刻返回** `{"task_id": "<自增或 uuid>", "state": "running"}`，下载在后台线程跑，**不能阻塞 HTTP 线程**（和 `/api/install` 一个套路）。
2. 落盘位置：`PROJECT_DIR`（和 `/api/upload_apk` 一致），文件名取 `name` → `Content-Disposition.filename` → URL 最后一段，都不是就以 `download.apk`；**必须保证以 `.apk` 结尾**，重名时加 `_1`/`_2` 后缀，不要静默覆盖已有包。
3. **流式写盘**：`urllib.request` 打开后按 1~8MB 读、边读边写，**不要 `read()` 整包进内存**（最大会到 800MB+）。
4. **断点续传**：先写 `<name>.part`，同时把进度写进内存字典；支持 `Range: bytes=<已有>-` 续传（服务端返回 206 才续，返回 200 就从头覆盖）。`resume: false` 时清空重下。
5. **超时与重试**：连接超时 30 秒、读取超时 60 秒（大文件别设全局 timeout），失败自动重试 2 次（间隔 3 秒 / 6 秒），仍失败则把 `.part` 保留（方便下次续传）并在状态里写明原因。
6. **进度可查**：`GET /api/download_status?task_id=<id>` 返回
   ```json
   {"task_id":"...","state":"running|done|failed","received":123456789,
    "total":336613183,"speed_mbps":4.7,"eta_sec":45,"path":"com.hsy.sygg_v18.apk",
    "error":"","sha256_ok":true}
   ```
   `total` 拿不到（无 `Content-Length`）时给 `-1`，前端显示「已下载 123.4 MB / 未知」。
7. **完成后**：`sha256` 若给了就校验；通过则 `.part` 改名为正式文件，并**自动出现在 `/api/apks` 里**（因为它就落在 `PROJECT_DIR`，这条应该天然成立，但要实测确认）。
8. `install_after: true` 时，下载成功直接复用现有安装链路（`resolve_apk` + `install_one` 线程），返回里带上 `installed_serials`。
9. **取消**：`POST /api/download_cancel?task_id=`，置标记位让下载线程在下一个分块检查后退出并删 `.part`。
10. 同时只允许 **1 个下载任务**（简单起见），第二个请求返回 `409 {"error":"已有下载任务在进行"}`。

### 3.2 前端：APK 选择区上方加一行「从 URL 下载」

- 在 `web/index.html` 的 APK 拖放/选择区（约 :590~605，`#apkSelect` 那一块）**上方**插一个折叠面板（默认收起，标题「⬇ 从链接下载安装包」）。
- 展开后：一个 URL 输入框 + 可选「保存为」（文件名）+ 可选「校验 SHA256」+ 「开始下载」按钮。
- 下载中显示：进度条 + `已下载 123.4 MB / 321.0 MB · 4.7 MB/s · 剩 45 秒`，每 1 秒轮询 `/api/download_status`。
- 完成：自动刷新 `state.apks`（复用 `api('apks')` 与现有的下拉渲染函数），**并把新包自动选中**（复用现有选中逻辑，别另写一套赋值）。
- 失败：显示后端 `error` 原文 + 「重试」按钮（重试时带 `resume: true`）。
- 复用现有 `api()` 封装、`$()`、`esc()`，样式跟现有控件一致，**不要引入任何 CSS/JS 库**。

## 四、硬约束（别踩这些坑）

1. **不要改现有接口的请求/响应结构**，尤其 `/api/install`、`/api/apks`、`/api/upload_apk`——现场脚本都按现在的字段在用。
2. **不要整包读进内存**，不要用 `urllib.request.urlopen(...).read()` 一把梭。
3. **不要阻塞主线程**：下载和安装都必须 `threading.Thread(daemon=True)`。
4. **文件编码**：`server.py` 里有中文，统一 UTF-8（无 BOM）；Windows 上打印中文别依赖控制台编码。
5. **不要动 `launcher.exe` 的打包逻辑**，只改 `web\` 下的源码；改完告诉我怎么重新打包/怎么用 `python web\server.py` 直接调试。
6. 下载目录就是 `PROJECT_DIR`，**不要新建 `downloads\` 子目录**（否则 `resolve_apk` 和 `/api/apks` 找不到它）。
7. 大文件（800MB+）下载过程要能让 Windows 资源管理器看到文件在长大（即边下边写，不要先落内存最后一次性 `write`）。

## 五、验收清单（自己跑通再交付）

1. 粘一个 ~300MB 的真实 CDN 地址 → 后台开始下载，网页进度条每秒钟在动，磁盘上出现 `<name>.part` 且在变大。
2. 下到一半刷新页面 / `Ctrl+C` 断一下 → 重新发起同 URL 带 `resume: true` → **从已下载位置继续**，不从头来。
3. 下完后 `状态=done`、`sha256_ok=true`（给了 sha 的情况）、文件名以 `.apk` 结尾、出现在 `/api/apks` 的列表里、网页下拉自动选中它。
4. 直接点现有的「安装到设备」→ 走的就是原来的安装流程，日志和以前一致。
5. 给一个错误 URL（404）→ 状态 `failed`、错误信息清楚、不留下 0 字节的正式文件。
6. 给一个非 apk 的 URL（比如 `latest.json`）→ 拒绝或自动加 `.apk` 后缀（按 3.1 第 2 条），不能出现后缀不符的文件。
7. 同时发两个下载请求 → 第二个拿到 `409`。
8. 下载过程中点「取消」→ 线程退出、`.part` 被删、状态变 `canceled`。
